你是一位资深的后端开发 + 测试数据专家，擅长为财务审批类系统生成真实感强、关联完整的模拟数据。

请为「财务单据智能风险审核系统」生成可直接导入 MySQL 的测试数据。

### 一、系统核心表（请按这些表生成数据）

1. 用户与权限相关
- user（用户）
- role（角色）
- permission（权限）
- user_role / role_permission（如果需要关联表）

2. 单据相关
- document（单据主表）
- document_item / document_detail（费用明细）
- attachment（附件）
- attachment_parse_result（附件解析结果）

3. 风险相关
- risk_analysis（风险分析主表）
- risk_item（风险项）
- risk_evidence（风险证据）
- risk_rule（风险规则，可选）

4. 审批相关
- approval_flow（审批流）
- approval_task（审批任务）
- approval_opinion（审批意见，如有）
- audit_log（审计日志）
- notification（通知，可选）

5. 报告
- report（风险审核报告）

### 二、数据要求

- 生成 **30~50 张单据**，覆盖不同状态：
  - draft（草稿）
  - pending_approval（待审批）
  - returned（退回）
  - rejected（驳回）
  - completed（已完成）
- 每张单据包含 2~6 条费用明细
- 部分单据要有对应的风险分析结果和风险项
- 已提交/已完成的单据要有审批任务和审批意见
- 已完成的单据要有对应的报告数据
- 数据要有关联性（外键能对上），不要出现孤立数据
- 金额、日期、单据编号要真实合理
- 单据编号格式参考：FY20261021-001

### 三、输出要求

请按以下顺序输出：

1. **建表 SQL**（如果我还没建表，请先给出完整的 CREATE TABLE 语句，字段尽量完整合理）
2. **清空表的 SQL**（方便重复导入）
3. **插入数据的 SQL**（按依赖顺序插入，保证外键正确）
4. 最后给出简要说明：生成了多少用户、多少单据、各状态数量等

### 四、技术约束

- 数据库：MySQL 8
- 字符集：utf8mb4
- 所有 SQL 可直接复制执行
- 主键使用自增 ID 或 UUID（你自行选择合理方案）
- 时间字段使用合理的 datetime
