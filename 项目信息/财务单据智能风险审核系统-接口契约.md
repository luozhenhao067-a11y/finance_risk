## 1. 接口设计原则

### 1.1 风格与约定

- RESTful，资源名词复数，动作用子资源或动词后缀表达（submit / approve / withdraw）。
- 统一前缀：`/api/v1`。前端 Axios `baseURL = VITE_API_BASE || '/api/v1'`，后端就绪后只改该环境变量，前端代码零改动。
- 请求体：`application/json; charset=utf-8`；附件上传：`multipart/form-data`；导出/下载：二进制流（`application/octet-stream` 或 `application/pdf` / `application/vnd.ms-excel`）。
- 时间格式：统一 `yyyy-MM-dd HH:mm:ss`（如 `2026-10-21 10:32:05`）；日期字段 `yyyy-MM-dd`。前端 mock 目前为分钟精度，后端返回秒级即可，前端按需截取。
- 金额：后端 `DECIMAL(14,2)`，JSON 序列化为 number，恒 2 位小数（如 `7000.50`）。前端不做精度运算，仅展示与回传。
- 分页参数：`page`（从 1 起）、`page_size`（默认 20，最大 100）；分页响应统一 `{ total, page, page_size, list }`。
- 排序参数：`sort_by` + `sort_order`（`asc` / `desc`），仅允许白名单字段。

### 1.2 统一响应格式

所有非二进制接口返回统一信封：

```json
{
  "code": 0,
  "message": "success",
  "data": { },
  "trace_id": "1a2b3c4d5e6f7a8b9c0d"
}
```

- `code = 0` 表示成功；前端响应拦截器判断 `'code' in body`，`code === 0` 时直接解包返回 `data`，否则抛出 `message`。
- HTTP 状态码约定：业务错误也返回 HTTP 200 + 非 0 `code`（前端拦截器按 `code` 处理）；认证失败、参数错误等亦可直接用 4xx/5xx HTTP 状态 + 同一信封结构，前端 axios error 拦截器统一兜底。
- `trace_id`：全链路追踪 ID，写入 `operation_log`，支持按 trace_id 串起一次请求全链路。

### 1.3 错误码约定

| code 区间 | 含义 | 典型场景 |
| --- | --- | --- |
| 0 | 成功 | — |
| 40001~40099 | 参数/校验错误 | 必填缺失、格式错误、金额不一致、附件类型/大小超限 |
| 40101~40199 | 未认证 / 凭证失效 | 未登录、token 过期、登录失败 |
| 40301~40399 | 无权限 / 数据越权 | 角色权限不足、访问他人单据 |
| 40401~40499 | 资源不存在 | 单据/附件/任务不存在 |
| 40901~40999 | 状态冲突 | 非法状态流转、重复审批操作、并发冲突（乐观锁） |
| 50001~50099 | 系统错误 | 内部异常、下游服务（OCR/规则引擎）失败 |

约定具体错误码（后端可扩展）：

| code | message 建议 | 说明 |
| --- | --- | --- |
| 40101 | 未登录或凭证已失效 | token 缺失/过期 |
| 40102 | 用户名或密码错误 | 登录失败 |
| 40103 | 账号已锁定，请 15 分钟后重试 | 连续 5 次失败锁定 15 分钟 |
| 40301 | 无权执行该操作 | 角色权限不足 |
| 40302 | 无权访问该数据 | 数据权限越权（本人/本部门/全量） |
| 40401 | 单据不存在 | |
| 40402 | 附件不存在 | |
| 40403 | 审批任务不存在 | |
| 40901 | 单据当前状态不允许该操作 | 状态机非法流转 |
| 40902 | 该审批任务已被处理 | 重复审批操作 |
| 40903 | 单据已被他人修改，请刷新后重试 | 乐观锁版本冲突 |

### 1.4 认证与鉴权

- 认证方式：JWT。登录成功后前端存入 `localStorage['finance-risk-audit-token']`，后续请求自动携带 `Authorization: Bearer <token>`。
- 有效期 2 小时；过期返回 40101，前端路由守卫跳转登录页。
- 密码 BCrypt 存储；登录连续失败 5 次锁定 15 分钟。
- 鉴权双层：
  - **功能权限（RBAC）**：四角色 `APPLICANT`（申请人）/ `DEPT_MANAGER`（部门负责人）/ `FINANCE`（财务审核人）/ `ADMIN`（系统管理员）。服务端强制校验，前端控制仅做体验。
  - **数据权限（三层）**：申请人仅本人单据；部门负责人本部门单据；财务/管理员全量。所有查询接口按此过滤，附件访问、风险查询、审批操作同规则。
- 审批操作防重放：幂等键 = `taskId + 单据版本号`；重复请求返回幂等结果或 40902。

### 1.5 权限矩阵（服务端必须按此校验）

| 操作 | APPLICANT | DEPT_MANAGER | FINANCE | ADMIN |
| --- | --- | --- | --- | --- |
| 创建单据 | 本人 | 本人 | 本人 | 本人 |
| 编辑/删除单据 | 本人 + draft/returned | 本人 + draft/returned | 本人 + draft/returned | 本人 + draft/returned |
| 提交 / 重提 / 撤回 | 本人单据 | 本人单据 | 本人单据 | 本人单据 |
| 审批通过/退回/驳回 | 否 | 本部门当前节点任务 | 全部当前节点任务 | 全部当前节点任务 |
| 确认完成（approved → completed） | 否 | 否 | 是 | 是 |
| 恢复驳回单据（rejected → draft） | 否 | 否 | 否 | 是 |
| 风险处理（handled/dismissed） | 否 | 本部门 | 是 | 是 |
| 重新分析 | 否 | 否 | 是 | 是 |
| 生成/导出报告 | 查看本人报告 | 查看本部门报告 | 生成+导出 | 生成+导出 |
| 审计日志 | 否 | 否 | 是 | 是 |
| 系统管理 | 否 | 否 | 否 | 是 |

## 2. 通用数据结构（TypeScript）

```typescript
// ---------- 用户与部门 ----------
interface User {
  id: string;              // 如 'u-wangfang'
  name: string;            // 如 '王芳'
  role: string;            // 角色名：'申请人' | '部门负责人' | '财务审核人' | '系统管理员'
  role_code: RoleCode;     // 'APPLICANT' | 'DEPT_MANAGER' | 'FINANCE' | 'ADMIN'
  dept: string;            // 部门名
  dept_id: string;         // 如 'dept-finance'
  avatar: string;          // 头像字符（姓名首字）
}

interface Dept {
  id: string;
  name: string;
  manager_id?: string;     // 部门负责人（审批任务按此路由）
  parent_id?: string;      // 部门树
}

// ---------- 单据 ----------
type DocType = '费用报销' | '差旅费报销' | '采购付款' | '合同付款' | '借款单';
type DocStatus = 'draft' | 'submitted' | 'analyzing' | 'pending_approval'
  | 'returned' | 'rejected' | 'approved' | 'completed';
type RiskLevel = 'none' | 'low' | 'mid' | 'high';

interface Document {
  id: string;
  doc_no: string;          // 'FY20261021-001'，FY + yyyyMMdd + '-' + 3位当日流水（服务端生成，防并发重复）
  doc_type: DocType;
  title: string;           // ≤100 字符
  applicant_id: string;
  applicant_name: string;
  dept_id: string;
  dept_name: string;
  project: string;         // ≤100 字符
  total_amount: number;    // = Σ明细金额，服务端强校验
  status: DocStatus;
  version: number;         // 初值 1，重提 +1
  current_node: string | null;  // 当前审批节点名；draft/returned 为 null，submitted/analyzing 为 '—'
  submit_time: string | null;   // 最近一次提交时间
  create_time: string;
  risk_level: RiskLevel;   // 冗余，随分析结果更新
  risk_count: number;      // 冗余，风险项数量
  queue_time: string;      // 展示辅助字段（'10:32' / '昨天'），后端可返回空串，由前端相对时间格式化
  remark?: string;
  delete_flag?: number;    // 逻辑删除标记
}

// ---------- 费用明细 ----------
interface DocumentDetail {
  id: string;
  doc_id: string;
  expense_type: string;    // 按 doc_type 限定可选集合，见 7.2
  expense_date: string;    // 'yyyy-MM-dd'，不得晚于当天
  amount: number;          // > 0，最多 2 位小数
  invoice_no: string;      // 报销类必填；借款单可为 '—'
  remark?: string;         // ≤200 字符
}

// ---------- 附件 ----------
type ParseStatus = 'parsing' | 'parsed' | 'failed';

interface Attachment {
  id: string;
  doc_id: string;
  file_name: string;       // 原始文件名
  size: number;            // 字节数
  size_label: string;      // 展示用（'1.2MB' / '860KB'），后端生成
  mime: string;            // 'application/pdf' | 'image/png' | 'image/jpeg'
  file_type: 'pdf' | 'image';
  storage_path?: string;   // MinIO 对象键，前端用 path 字段
  path: string;            // 前端使用：'/files/{doc_no}/v{version}/{file_name}'
  uploaded_at: string;
  parse_status: ParseStatus;
}

interface ParseField { label: string; value: string; confidence: number; position?: string }
interface ParseResult {
  id: string;
  doc_id: string;
  attachment_id: string;
  file_name: string;
  page: number;            // 页码
  raw_text?: string;       // 解析文本
  fields: ParseField[];    // 发票号码/开票日期/销售方/金额合计/税额/合同编号/本期应付/付款比例 等，按 doc_type 模板
  confidence: number;      // 整体置信度 0-100
}

// ---------- 审批 ----------
type InstanceStatus = 'running' | 'completed' | 'returned' | 'rejected' | 'cancelled';
type TaskStatus = 'pending' | 'done' | 'cancelled';
type TaskAction = 'approved' | 'returned' | 'rejected';
type OpinionAction = 'submit' | 'resubmit' | 'approve' | 'return' | 'reject' | 'withdraw';

interface ApprovalInstance {
  id: string;
  doc_id: string;
  status: InstanceStatus;
  current_node: string | null;
}

interface ApprovalTask {
  id: string;
  instance_id: string;
  doc_id: string;
  node: string;            // '部门经理审批' | '财务专员审核' | '财务经理复核'
  assignee: string;        // 被分配人姓名
  status: TaskStatus;
  action?: TaskAction;     // 完成后
  finished_at: string | null;
}

interface ApprovalOpinion {
  id: string;
  doc_id: string;
  task_id: string | null;  // 提交/撤回类记录为 null
  node: string;            // '申请人提交' 用于提交类记录
  user: string;            // 操作人姓名
  action: OpinionAction;
  opinion: string;         // ≤500 字符
  created_at: string;
}

// ---------- 风险 ----------
type RiskItemStatus = 'open' | 'handled' | 'dismissed';
type Recommendation = 'pass' | 'supplement' | 'manual_review' | 'reject_suggest';

interface RiskAnalysis {
  id: string;
  doc_id: string;
  doc_version: number;     // 对应单据版本
  status: 'running' | 'completed' | 'failed';
  overall_level: RiskLevel;   // = max(风险项等级)；无风险项为 none
  high_count: number;
  mid_count: number;
  low_count: number;
  recommendation: Recommendation;
  recommendation_label: string;  // '建议通过' | '补充材料' | '人工复核' | '建议驳回'
  summary: string;          // 分析摘要
  trigger_type: 'auto' | 'resubmit' | 'manual';
  triggered_by?: string;    // manual 时记录触发人
  analyzed_at: string | null;
}

interface RiskEvidence {
  id: string;
  risk_item_id: string;
  doc_id: string;
  attachment_id: string;
  page: number;
  snippet: string;         // 原文片段（高亮依据）
  confidence: number;
}

interface RiskItem {
  id: string;
  doc_id: string;
  rule_code: string;       // 'R-01' ~ 'R-10'，或扩展规则 'R-EXT'
  level: 'high' | 'mid' | 'low';
  title: string;
  basis: string;           // 判断依据
  evidence?: string;       // 证据摘要文案（前端 mock 使用）
  suggestion: string;      // 处理建议
  page: number;
  confidence: number;
  status: RiskItemStatus;
  handled_by?: string;
  handled_at?: string;
  handle_opinion?: string;
  evidences?: RiskEvidence[];  // 详情接口内嵌返回
}

// ---------- 日志 ----------
interface OperationLog {
  id: string;
  doc_id: string | null;   // 系统级操作（如规则配置）为 null
  action: string;          // 见 7.6 动作清单
  operator: string;        // 操作人姓名，系统动作为 '系统'
  role: string;            // 角色名或 '系统'
  detail: string;          // ≤500 字符
  created_at: string;
}

// ---------- 报告 ----------
interface AmountCheck { name: string; doc_amount: number; parsed_amount: number; diff: number; conclusion: string; is_total?: boolean }
interface VendorRisk { name: string; score: number; level: RiskLevel; note: string }
interface ReviewRecord { name: string; role: string; avatar: string; content: string; created_at: string }

interface Report {
  id: string;
  doc_id: string;
  report_no: string;       // 'RPT-20261021-0087'，RPT-yyyyMMdd-4位流水
  generated_at: string;
  overall_level: RiskLevel;
  overall_text: string;    // '整体风险：高风险（4 项：高 2 · 中 1 · 低 1）'
  recommendation_label: string;
  summary: string;
  amount_checks: AmountCheck[];   // 含合计行 is_total: true
  vendor: VendorRisk | null;      // 无供应商单据为 null（前端显示'不适用'）
  reviews: ReviewRecord[];        // 人工复核意见时间线
}

// ---------- 工作台 ----------
interface Notification { id: string; doc_id: string; title: string; time: string; read: boolean }
interface Todo { id: string; doc_id: string; level: RiskLevel; text: string }

interface Page<T> { total: number; page: number; page_size: number; list: T[] }
```

## 3. 完整接口清单

> 路径均相对 `/api/v1`。所有接口除标注"公开"外均需 Bearer token。数据权限按 1.5 矩阵过滤。

### 3.1 认证与用户

#### POST `/auth/login`（公开）

说明：登录，返回 JWT 与用户信息。

请求 Body：

```json
{ "username": "王芳", "password": "123456", "remember": false }
```

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| username | string | 是 | 用户名 |
| password | string | 是 | 密码 |
| remember | boolean | 否 | 记住用户名（前端持久化用户名，非 token 长效） |

响应 `data`：

```json
{
  "token": "eyJhbGciOiJIUzI1NiJ9...",
  "user": {
    "id": "u-wangfang", "name": "王芳", "role": "财务审核人",
    "role_code": "FINANCE", "dept": "财务部", "dept_id": "dept-finance", "avatar": "王"
  }
}
```

错误：40001（用户名/密码为空）、40102（账号或密码错误）、40103（账号锁定）。

#### POST `/auth/logout`

说明：登出，服务端可作废 token（JWT 无状态时可仅前端删除）。

请求 Body：无。

响应 `data`：`null`。错误：40101。

#### GET `/auth/me`

说明：当前用户信息与权限点，用于刷新页面恢复会话。

响应 `data`：

```json
{
  "user": { "id": "u-wangfang", "name": "王芳", "role": "财务审核人", "role_code": "FINANCE", "dept": "财务部", "dept_id": "dept-finance", "avatar": "王" },
  "permissions": ["doc.view.all", "risk.handle", "report.generate", "report.export", "log.view"]
}
```

错误：40101。

```json
    { "id": "td001", "doc_id": "d001", "level": "high", "text": "FY20261021-001 差旅报销待审批" }
  ],
  "notifications": [
    { "id": "n001", "doc_id": "d001", "title": "FY20261021-001 风险分析完成", "time": "10 分钟前", "read": false }
  ],
  "recent_documents": [ /* Document[]，最多 6 条，按 create_time 倒序 */ ]
}
```

错误：40101。

#### PUT `/notifications/read-all`

说明：全部通知标记已读。Body 无。响应 `data`：`null`。

#### GET `/notifications`

说明：通知列表（分页，未读在前）。Query：`page`、`page_size`。响应 `Page<Notification>`。

### 3.3 单据

#### GET `/documents`

说明：单据分页列表（按角色数据权限过滤）。

Query 参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| page | int | 否 | 默认 1 |
| page_size | int | 否 | 默认 20，最大 100 |
| keyword | string | 否 | 模糊匹配 doc_no / title / applicant_name / dept_name / project |
| doc_type | string | 否 | 五类之一 |
| status | string | 否 | DocStatus 之一 |
| risk_level | string | 否 | none/low/mid/high |
| date_from / date_to | string | 否 | 提交时间范围，`yyyy-MM-dd` |
| sort_by | string | 否 | `amount` / `submit_time` / `create_time`，默认 create_time |
| sort_order | string | 否 | asc / desc，默认 desc |

响应 `data`：`Page<Document>`。错误：40101、40001（非法枚举/日期）。

#### POST `/documents`

说明：创建单据（含明细与附件元数据），可保存草稿或直接提交。对应前端"新建单据"页两个按钮。

请求 Body：

```json
{
  "doc_type": "差旅费报销",
  "title": "10月上海出差差旅报销",
  "dept_id": "dept-market",
  "dept_name": "市场部",
  "project": "华东区渠道大会",
  "details": [
    { "expense_type": "交通费", "expense_date": "2026-10-15", "amount": 1280,
      "invoice_no": "INV-88910234", "remark": "上海至北京高铁" },
    { "expense_type": "住宿费", "expense_date": "2026-10-16", "amount": 4860,
      "invoice_no": "INV-88910451", "remark": "北京酒店3晚" }
  ],
  "attachments": [
    { "file_name": "发票.png", "size_label": "860KB", "mime": "image/png", "file_type": "image" }
  ],
  "submit": false
}
```

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| doc_type | string | 是 | 五类之一 |
| title | string | 是 | ≤100 字符，非空 |
| dept_id | string | 是 | 默认当前用户部门 |
| dept_name | string | 否 | 冗余展示字段 |
| project | string | 是 | ≤100 字符 |
| details | array | 是 | ≥1 条；字段规则见 4.4 校验表 |
| attachments | array | 否 | 附件元数据（文件实体经 3.5 上传接口先行上传） |
| submit | boolean | 否 | true = 创建并提交（走提交链路）；false = 保存草稿 |

响应 `data`：创建的 `Document`。创建时服务端：生成 `doc_no`、`total_amount = Σ明细`、`status = submit ? 'submitted' : 'draft'`、`version = 1`、记录日志"创建单据"。`submit = true` 时在事务内生成快照 + 审批实例 + 首个任务，并异步触发解析/分析。

错误：40001（校验失败，逐字段 message）、40101、40901。

#### GET `/documents/{id}`

#### POST `/documents/{id}/submit`

说明：提交审批（draft → submitted）。服务端做提交强校验（见 4.4），通过后事务内：生成不可变快照 → 创建审批实例与首个任务 → 发 MQ 触发附件解析与风险分析；单据异步流转 submitted → analyzing → pending_approval。

```json
  "status": "submitted",
  "version": 1,
  "snapshot_version": 1,
  "approval_instance_id": "ai001",

  "analysis_task_id": "rt-8001"

```

说明：退回重提（returned → submitted），`version + 1`，生成新快照、重建审批实例、全量重新分析；意见表追加 `action = resubmit` 记录。

响应 `data`：同 submit 结构。错误：40901（非 returned）、40301（非本人）。

#### POST `/documents/{id}/withdraw`

说明：撤回（pending_approval → returned）。当前节点 pending 任务置 cancelled，实例置 returned，意见追加 `action = withdraw`。

响应 `data`：更新后 `Document`。错误：40901、40301。

#### POST `/documents/{id}/complete`

说明：财务/管理员确认完成（approved → completed，终态，归档）。响应 `data`：更新后 `Document`。错误：40301、40901。

#### POST `/documents/{id}/restore`

说明：管理员恢复驳回单据（rejected → draft），恢复原因强制写入审计日志。

请求 Body：`{ "reason": "线下核验完成，申请人修正后可重新提交" }`（必填，非空，≤200 字符）。

响应 `data`：更新后 `Document`。错误：40301（非 ADMIN）、40001（reason 缺失）、40901（非 rejected）。

#### GET `/documents/{id}/snapshots`

说明：版本快照列表（财务/管理员版本回溯用）。响应 `data`：

说明：指定版本快照详情，返回 `{ snapshot, payload: { document, details, attachments } }`。`payload` 只读，任何接口不得修改。

说明：单据维度操作日志（时间倒序）。Query：`page`、`page_size`。响应 `Page<OperationLog>`。权限：财务/管理员 + 单据可见者（申请人本人、本部门负责人）。

#### POST `/documents/{id}/approve`

> 前端实际调用路径（api/index.js）。Spec 6.2 中的任务级路径 `POST /approvals/tasks/{taskId}/approve|return|reject` 为等价备选，后端二选一实现即可；若实现任务级路径，前端仅需替换该行调用。

说明：审批操作（通过 / 退回 / 驳回）。服务端校验：当前用户 = 当前节点任务的 assignee；任务 status = pending；单据 status = pending_approval；乐观锁版本比对。

请求 Body：

```json
{ "action": "approve", "opinion": "同意报销，请财务复核发票明细。" }
```

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| action | string | 是 | `approve` / `return` / `reject` |
| opinion | string | 条件必填 | return/reject 必填（≤500 字符）；approve 可选（缺省"同意，审批通过。"；存在 open 的高风险项时，前端二次确认内容写入 opinion） |

响应 `data`：

```json
{
  "doc_id": "d001",
  "doc_status": "pending_approval",
  "current_node": "财务经理复核",
  "next_task": { "id": "task002", "node": "财务经理复核", "assignee": "王芳", "status": "pending" }
}
```

流转逻辑（与前端 mock 一致）：

| action | 位置 | 结果 |
| --- | --- | --- |
| approve | 非最后节点 | 当前任务 done（action=approved），生成下一节点任务，doc 保持 pending_approval，current_node 更新 |
| approve | 最后节点（财务经理复核） | doc → approved，instance → completed，current_node = '审批完成'，自动生成报告 |
| return | 任意节点 | doc → returned，当前任务 done（action=returned），其余 pending 任务 cancelled，instance → returned |
| reject | 任意节点 | doc → rejected（终态），同上，instance → rejected |

错误：40101、40301（非 assignee）、40401、40901（状态不允许）、40902（任务已处理）、40903（版本冲突，携带最新 version 供前端刷新）。

说明：审批流转详情（进度条 + 意见时间线）。

响应 `data`：

```json

    { "node": "部门经理审批", "status": "done", "person": "刘洋", "opinion": { /* ... */ } },
```

## 4. 关键业务规则

### 4.1 单据编号生成

- 格式：`FY` + `yyyyMMdd` + `-` + 3 位当日流水（`FY20261021-001`）。
- 服务端生成，需防并发重复（唯一索引 + 重试或 Redis 计数）。

### 4.2 提交异步链路

提交/重提后单据进入异步链路（前端 mock 用 setTimeout 模拟 0.7s + 1.8s 两步，真实后端用 MQ 解耦）：

```
submitted（事务内：快照 + 审批实例 + 首个任务 + 解析/分析任务创建）
   → analyzing（附件解析任务完成，规则引擎执行中）
   → pending_approval（分析完成；失败重试 3 次后标注 analysis_failed 仍进入待审批）
```

- 前端详情页通过轮询 `GET /documents/{id}` 感知状态流转（建议 2~3s 间隔），不依赖推送。
- 分析结果生成后同步更新 document 冗余字段 risk_level / risk_count。

### 4.3 状态机流转矩阵（接口约束）

| 当前状态 | 接口 | 操作人 | 目标状态 | 附加规则 |
| --- | --- | --- | --- | --- |
| draft | PUT /documents/{id} | 本人 | draft | doc_type 不可变 |
| draft | DELETE /documents/{id} | 本人 | 删除 | |
| draft | POST /documents/{id}/submit | 本人 | submitted | 4.4 强校验 |
| submitted | 系统 | 系统 | analyzing | 事务内快照+实例+任务 |
| analyzing | 系统 | 系统 | pending_approval | 失败重试 3 次后 analysis_failed 进入 |
| pending_approval | POST /documents/{id}/approve（approve，非最后节点） | 当前节点 assignee | pending_approval | current_node 更新，生成新任务 |
| pending_approval | approve（最后节点） | 当前节点 assignee | approved | 实例 completed，自动生成报告 |
| pending_approval | approve（return） | 当前节点 assignee | returned | 意见必填；实例 returned；未完成任务 cancelled |
| pending_approval | approve（reject） | 当前节点 assignee | rejected | 意见必填；终态 |
| pending_approval | POST /documents/{id}/withdraw | 本人 | returned | 当前任务 cancelled，实例 returned |
| returned | POST /documents/{id}/resubmit | 本人 | submitted | version + 1，新快照、重建实例、全量重分析 |
| rejected | POST /documents/{id}/restore | 管理员 | draft | 恢复原因必填，写日志 |
| approved | POST /documents/{id}/complete | 财务/管理员 | completed | 终态 |

除上表外的任何迁移一律 40901。

### 4.4 提交校验规则（服务端强校验，逐条 message 返回）

| 校验项 | 规则 | 失败 message |
| --- | --- | --- |
| title | 非空，≤100 字符 | 请填写单据标题 |
| project | 非空，≤100 字符 | 请填写费用项目 |
| details | ≥1 条 | 请至少添加一条费用明细 |
| expense_type | 必填，且在 doc_type 对应字典内（见 7.2） | 请补全费用明细的类型、日期与金额 |
| expense_date | `yyyy-MM-dd`，不得晚于当天 | 费用日期格式应为 YYYY-MM-DD / 费用日期不能晚于今天 |
| amount | > 0，最多 2 位小数 | 金额最多保留 2 位小数 |
| total_amount | = Σ明细金额（2 位小数，容差 ¥0.01） | 合计金额与明细不一致 |
| invoice_no | 报销类（费用报销/差旅费报销）必填；格式 `^(\d{8}\|\d{10}\|(INV\|HT)-\d+)$`i | 报销类单据发票号必填 / 发票号格式不正确 |
| invoice_no | 借款单可为 '—' | — |
| remark | ≤200 字符 | — |
| 附件类型 | 仅 pdf/png/jpg/jpeg，单文件 ≤20MB | 格式不支持，仅支持 PDF / PNG / JPG |
| 必需附件 | 费用报销/差旅费报销 ≥1 个文件名含"发票/票据"的附件 | 报销类单据必须上传至少 1 个发票附件 |
| 必需附件 | 采购付款/合同付款必须含文件名含"合同"的附件 | 采购付款/合同付款必须上传合同附件 |

校验失败返回 40001，单据保持 draft。

### 4.5 审批通过与高风险

- 审批通过时若存在 `status = open` 的 high 级风险项，前端弹二次确认，确认内容写入 `opinion` 与日志。
- 风险分析是建议，不做自动决策：无论等级高低，单据一律进入 pending_approval 由人工决策。

### 4.6 整体风险等级与处理建议

- `overall_level = max(风险项等级)`（high > mid > low），无风险项为 `none`；结合数量展示如"高风险（4 项：高 2 · 中 1 · 低 1）"。
- 处理建议映射（规则引擎默认值，可配置覆盖）：存在 high → `manual_review`（金额/合同类可升级 `reject_suggest`）；仅 mid → `supplement`；仅 low → `pass` 或 `manual_review`；none → `pass`。

### 4.7 并发控制

- 审批/撤回/重提操作携带单据 `version` 做乐观锁；冲突返回 40903 并携带服务端最新 version，前端提示刷新。
- 同一任务重复审批：幂等键 taskId + 单据版本，返回 40902 或幂等结果。

### 4.8 前端 mock 行为还原对照（后端实现参考）

| 前端 mock 行为 | 后端应有行为 |
| --- | --- |
| localStorage 单库全量状态 | 分表 + 分页查询，数据权限 SQL 过滤 |
| 提交后 setTimeout 状态流转 | MQ 异步任务链，任务表可查进度 |
| parse_status 恒为 parsed | parsing → parsed / failed 真实流转 |
| buildRiskAnalysis 每次清理旧版分析结果 | 按 doc_version 保留历史分析，最新版返回 |
| approveDocument 按 current_node 找 pending 任务 | 严格按 assignee + task.status + 乐观锁校验 |
| ensureReport 幂等生成 | 事务内幂等（doc_id 唯一索引），手动覆盖重新生成 |
